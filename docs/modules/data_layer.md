# Data Layer

Pokémon data flows through a strict three-tier cache. Never fetch from PokéAPI directly in a component — always go through `src/services/pokemonDataCache.js`.

---

## Cache Architecture

**File:** `src/services/pokemonDataCache.js`

All data fetches are funneled through `fetchJsonCached(url, storageKey, ttl)`. The three tiers in resolution order:

### Tier 1 — In-Memory Map
Per-session JavaScript `Map`. Zero-latency on repeat access within a tab. Cleared on page refresh.

### Tier 2 — Browser Storage + TTL
- **Reference data** (generations, items, natures, static lists): `localStorage`, 30-day TTL.
- **Volatile data** (detail docs, move data): `sessionStorage`, 24-hour TTL.
- Cache keys are versioned: `ptb:pokemon-data:${CACHE_VERSION}:*`. **Bump `CACHE_VERSION` in `pokemonDataCache.js` whenever the shape of any cached file changes.** A version bump triggers a one-time sweep that purges all old-format entries from storage, preventing stale-format UI breakage for long-TTL users after a deploy.

### Tier 3 — Network
Two network sources, in preference order:
1. **Static pre-baked JSON** in `public/data/` — preferred. `cache-manifest.json` declares which static files exist. `getStaticPokemonDetail(id)` consults the manifest before falling back.
2. **PokéAPI** (`VITE_POKEAPI_BASE_URL`) — fallback only. Used for Pokémon not covered by the static cache (IDs > the last baked batch) and for data types not yet pre-baked.

## Static Cache Files (`public/data/`)

Generated by `scripts/build-pokemon-cache.mjs`. Never edit these by hand.

| File | Content |
|------|---------|
| `pokemon-index.json` | 1025 entries: `{ id, name, types[], generation }` — the master list |
| `generations.json` | Generation metadata |
| `items.json` | Full item catalog |
| `natures.json` | Nature table with stat modifiers |
| `moves/` | Per-move detail files |
| `pokemon/{id}.json` | Full detail per Pokémon (for pre-baked IDs) |
| `cache-manifest.json` | Declares which `pokemon/{id}.json` files exist |
| `games.json` | The selectable games for the "by game" filter — see below |

**Rebuild commands:**
```bash
npm run data:cache                             # index, reference data, manifest
npm run data:cache:details                     # also fetch details for IDs 1–151
node scripts/build-pokemon-cache.mjs --all-details  # all 1025
```

After adding new static files, always regenerate `cache-manifest.json` via one of the above commands.

## Selectable Games (`games.json`)

Built separately by **`node scripts/build-games.mjs`** (not by `data:cache`), from a
curated `GAMES` table mapping each game to its PokéAPI Pokédex slug(s) plus the form
suffix groups native to it. Adding a game is one row there followed by a rebuild;
`getPokedex` skips unknown slugs, so a typo drops the game rather than failing.

Per game the file carries `{ key, label, generation, count, formSuffixes, dexes[], pokemonIds[] }`,
where `dexes` keeps each regional sub-dex separately **in in-game order** (Central /
Coastal / Mountain Kalos) so the builder can render them as sections.

Two rules learned while adding Pokémon Champions (2026-09-04):

- **`closedRoster: true`** marks a game whose Pokédex *is* its whole legal roster,
  with no transfer-in from earlier generations. `buildGameSections` then omits the
  trailing "National Pokédex" section, which for Champions would otherwise offer
  ~800 unusable Pokémon. Only set it for battle-only titles.
- **Legends: Z-A** (added 2026-09-08) is the second closed roster, and takes two
  dexes: Lumiose (232) plus Hyperspace (132), the Mega Dimension DLC's. Only the
  48 PokéAPI Megas attach; its own newer Megas are blocked by an id threshold
  that needs replacing with a per-game form group first — see `docs/wounds.md`
  2026-09-08 before changing that.
- A closed roster also **requires the form's base species to be in the dex.** The
  generic matcher takes any form whose suffix the game allows — fine for an open
  game, but it gave Champions Mega Mewtwo, Mega Rayquaza and Mega Latios (48 of
  102 matched forms were such orphans), i.e. exactly the restricted legendaries
  the format excludes.

Two narrowings sit between this file and the UI, and both silently drop unknown
fields — **anything a view reads off a game object must be added to them**:
`useReferenceStore.fetchReferenceData` (keeps the light fields) and
`usePokedexStore.getGameSets` (keeps `{ ids, generation, dexes }`).

A game's cover art is `src/assets/gameLogos/<game key>.png`, auto-registered by
that folder's `index.js`; a game without one falls back to the franchise logo.

## Pokémon List Loading

`usePokedexStore` loads `pokemon-index.json` once on first use via `usePokedex()` hook. The full list (1025 entries) is held in memory and filtered/searched/paginated **entirely client-side**. There is no Firestore query for the Pokémon list — that was a previous architecture that caused performance issues (see `docs/wounds.md`).

---

## Detail Loading

The Pokédex detail panel lazy-loads on card click via `getStaticPokemonDetail(id)`:

1. Check `cache-manifest.json` for the id.
2. If present: fetch `public/data/pokemon/{id}.json` (static, fast).
3. If absent: fetch from PokéAPI, cache in sessionStorage.

The Firestore `pokemons` collection at `artifacts/pokemonTeamBuilder/pokemons` is a legacy seed and is no longer the primary detail source. The static cache supersedes it for all pre-baked IDs.

## Sprites

**File:** `src/utils/pokemonSprites.js`

Sprites are loaded from `raw.githubusercontent.com` (PokeAPI sprites repo), not bundled locally. The `getPokemonFrontSpriteUrl(id, shiny)` function derives the URL from the Pokémon ID. The PWA service worker (via `vite-plugin-pwa`) caches sprite responses at runtime.

All sprite images must use `image-rendering: pixelated` (applied via `.sprite-img` class). Do not apply CSS smoothing filters to sprites.

---

## Type Data

**File:** `src/constants/types.js`

The full Gen-6+ type chart. Structure:
```js
typeChart[attackingType] = {
  damageTaken: { [defendingType]: multiplier },  // 0, 0.5, 1, 2
  damageDealt: { [defendingType]: multiplier }
}
```

Also exports: `typeColors` (type → hex color), `typeIcons` (type → imported PNG from `src/assets/typeIcons/`).

The type coverage engine in `useActiveTeamStore` uses `analyzeTeam` from `src/utils/teamAnalysis.js`, which multiplies per-Pokémon `damageTaken` values across the team to derive team-level weaknesses and resistances.

## i18n

**File:** `src/constants/translations.js`

All user-facing strings in a flat key→locale→value map. `useTranslation()` (`src/hooks/useTranslation.js`) resolves keys using the active language from `useLanguageStore`. Never hardcode UI strings in JSX — always add to `translations.js` and resolve via the hook.
